# Contributing

This repository is the Megabuyte plugin marketplace. The plugin's skills are written once in `src/` and assembled by `build.py` into `plugins/megabuyte/skills/`, which is what Claude, ChatGPT and Codex install.

## Setup

Enable the pre-commit hook once per clone:

```bash
git config core.hooksPath .githooks
```

Requires Python 3.9 or later. No other packages are needed.

## Layout

```
VERSION                     current plugin version
build.py                    assembles and validates the skills
src/
  shared/                   files every skill carries: edit them HERE only
    references/             conventions.md, brand.md
    scripts/                brand_setup.py, export_pdf.py, finish_export.py
    assets/                 Lato fonts + OFL licence, logos
  skills/<name>/            what is unique to each skill: SKILL.md and evals/
plugins/megabuyte/
  skills/                   GENERATED by build.py: never edit, always commit
  .claude-plugin/           Claude plugin manifest (version set by build.py)
  .codex-plugin/            Codex/ChatGPT plugin manifest (version set by build.py)
  .mcp.json                 MCP server definition
.githooks/pre-commit        runs build.py and stages its output
```

## Making a change

1. Edit the file in `src/shared/` (a rule for every skill) or in `src/skills/<name>/SKILL.md` (one skill).
2. Bump the number in `VERSION`:
   - patch (x.y.z+1) for wording fixes
   - minor (x.y+1.0) for new rules or a new skill
   - major (x+1.0.0) for changes that alter outputs subscribers rely on
3. Stage your changes and commit. The pre-commit hook rebuilds `plugins/megabuyte/skills/`, sets the version in both plugin manifests, and stages the result.

The hook refuses to run while `src/`, `VERSION`, `CHANGELOG.md` or `build.py` has unstaged changes, because the build would otherwise include work you aren't committing.

Bump the version for every change to the skills. Installed plugins only pick up an update when the plugin version changes.

## Adding a skill

Create `src/skills/<new-name>/SKILL.md`. Its frontmatter `name` must equal the folder name. Refer to shared files by their paths inside the built skill (`references/conventions.md`, `references/brand.md`, `scripts/...`). There's no need to copy them. Then bump the version (`minor`) and commit.
